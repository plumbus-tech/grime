# Working on grime together

Two lanes, one contract. You can work all day in your lane without touching
the other person's files.

| Lane | owns | typical work |
|---|---|---|
| **A — platform/async** | `src/core/`, `src/backend/`, `src/actions/act_exec.c`, `act_http.c`, `scripts/` | loop, devices, hotplug, new OS backends, async actions |
| **B — brain** | `src/engine/`, `src/config/`, `tests/` | walk semantics, config format, validation, engine tests |
| **shared contract** | `include/grime/*.h`, `docs/CONFIG.md` | changes need both of you |

`.github/CODEOWNERS` encodes this (replace `@FRIEND` with the real handle).

## Rules that keep us from colliding
1. **Branch per feature**, PR into `main`, CI green (`make CFLAGS=-Werror`, `make test`, `make check-configs`). Don't push to `main` directly.
2. **Header changes go in their own small PR** first (just the `.h` + stubs if needed), both approve, merge, then each side rebases and builds on it. Never mix a contract change into a feature PR.
3. **Adding an action touches one file**: create `src/actions/act_<name>.c`, define a `grime_action_type`, `GRIME_REGISTER_ACTION(it)`. The Makefile globs sources and actions self-register, so no shared file changes. Add a row to `docs/CONFIG.md`.
4. **Adding a test** = new `tests/test_<thing>.c` with its own `main` (picked up automatically). Prefer new files over growing someone else's.
5. **Formatting:** `.clang-format` + `.editorconfig`; run `make fmt` before pushing so diffs are only real changes.
6. **Configs:** `configs/default.json` is regenerated by a script, so edit personal keymaps in `configs/examples/<you>.json` or `~/.config/grime/config.json`.
